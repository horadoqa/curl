Como realizar a autenticação de um usuário utilizando o endpoint /login, enviar credenciais com o cURL e utilizar o token retornado em requisições que exigem autenticação.

CONCEITO / 08 HTTP / AUTH

Autenticação com ServeRest

cURL / Login / Bearer Token

Realizando o Login

No ServeRest, podemos realizar a autenticação de um usuário por meio do endpoint /login.

Para isso, utilizamos uma requisição POST, enviando o e-mail e a senha do usuário no corpo da requisição em formato JSON.

Requisição 

curl -X POST https://serverest.dev/login \ -H "Content-Type: application/json" \ -d '{     "email": "hordoqa@email.com",     "password": "1q2w3e4r" }'

Entendendo a Requisição

O comando utiliza algumas opções importantes do cURL para construir a requisição HTTP.

  • -X POST define o método HTTP como POST.
  • https://serverest.dev/login é o endpoint responsável pelo processo de login.
  • Content-Type: application/json informa ao servidor que os dados enviados estão no formato JSON.
  • -d '{...}' define o corpo da requisição contendo as credenciais do usuário.

Corpo da Requisição

O corpo enviado para o endpoint de login contém o e-mail e a senha utilizados na autenticação. 

{    "email": "hordoqa@email.com",    "password": "1q2w3e4r"}

O servidor utiliza essas informações para validar as credenciais do usuário.

Resposta de Sucesso

Quando o e-mail e a senha estão corretos, o ServeRest retorna uma resposta contendo uma mensagem de sucesso e um token de autenticação. 

{    "message": "Login realizado com sucesso",    "authorization": "Bearer eyJhbGciOiJIUzI1NiIs..."}

Token de Autenticação

O campo authorization contém o token que poderá ser utilizado posteriormente para acessar endpoints que exigem autenticação. 

"authorization": "Bearer eyJhbGciOiJIUzI1NiIs..."

O prefixo Bearer indica que estamos utilizando um token do tipo Bearer para autenticar a requisição.

Utilizando o Token

Depois de realizar o login, podemos utilizar o token retornado pelo servidor no header Authorization. 

curl -X GET https://serverest.dev/usuarios \ -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."

Nesse caso, o token é enviado junto com a requisição para que o servidor possa identificar e autenticar o cliente.

Header Authorization

A autenticação é realizada por meio do header Authorization, que recebe o tipo de autenticação e o token. 

Authorization: Bearer <TOKEN>

Fluxo de Autenticação

O processo de autenticação pode ser dividido em três etapas principais:

  • Realizar o login enviando e-mail e senha.
  • Receber o token de autenticação retornado pelo servidor.
  • Enviar o token no header Authorization das requisições protegidas.

Login vs Requisição Autenticada

Etapa Requisição
Login POST /login
Credenciais E-mail e senha no corpo JSON.
Resposta Token de autenticação.
Autenticação Authorization: Bearer TOKEN
Endpoint protegido GET /usuarios

Exemplo Completo

Podemos executar o login e utilizar o token retornado em uma segunda requisição. 

curl -X POST https://serverest.dev/login \ -H "Content-Type: application/json" \ -d '{     "email": "hordoqa@email.com",     "password": "1q2w3e4r" }'

Após obter o token, ele pode ser enviado na próxima requisição: 

curl -X GET https://serverest.dev/usuarios \ -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."

Resumindo

O processo de autenticação com o ServeRest utiliza uma sequência simples: 

POST /login      ↓Credenciais      ↓Token      ↓Authorization: Bearer TOKEN      ↓Endpoint protegido
QA Note

Em testes de API, o fluxo de autenticação normalmente começa pelo login. A resposta fornece um token, que deve ser armazenado e enviado posteriormente no header Authorization das requisições que exigem autenticação.
