Autenticação com cURL

cURL / Authentication

Por que utilizar autenticação?

Algumas APIs exigem que o cliente esteja autenticado antes de permitir o acesso a determinados recursos.

O cURL permite enviar informações de autenticação de diferentes formas. Duas das mais comuns são:

  • Basic Authentication
  • Bearer Token

Basic Authentication

Na autenticação Basic, o usuário e a senha são enviados por meio do header Authorization.

No cURL, podemos utilizar a opção -u, também conhecida como --user, para informar as credenciais. 

curl -u usuario:senha https://api.exemplo.com/usuarios

Header Authorization

O cURL transforma as credenciais para o formato utilizado pelo protocolo HTTP e envia um header semelhante a: 

Authorization: Basic <credenciais>

Por exemplo: 

curl -u joao:123456 https://api.exemplo.com/usuarios
Segurança

A autenticação Basic não significa que usuário e senha sejam protegidos durante o transporte por si só. Em aplicações reais, a comunicação deve utilizar HTTPS para proteger as credenciais durante a transmissão.

Bearer Token

Outra forma muito comum de autenticação é o uso de um Bearer Token.

Nesse modelo, o cliente primeiro obtém um token, normalmente por meio de um endpoint de login. Depois, esse token é enviado nas requisições que exigem autenticação.

Header Authorization

O token é enviado no header: 

Authorization: Bearer <token>

No cURL: 

curl -H "Authorization: Bearer <token>" \https://api.exemplo.com/usuarios

Entendendo o Header

O header de autenticação possui três elementos importantes:

  • Authorization — nome do header utilizado para autenticação.
  • Bearer — indica o tipo de credencial utilizada.
  • <token> — representa o token de acesso fornecido pela API.

Basic vs Bearer Token

Autenticação Utilização
Basic Utiliza usuário e senha por meio do header Authorization.
Bearer Utiliza um token de acesso enviado no header Authorization.

Exemplo com o ServeRest

No ServeRest, podemos realizar o login enviando as credenciais para o endpoint de autenticação. 

curl -X POST https://serverest.dev/login \-H "Content-Type: application/json" \-d '{    "email": "hordoqa@email.com",    "password": "1q2w3e4r"}'

Se as credenciais forem válidas, a API retorna um token que poderá ser utilizado em requisições que exigem autenticação.

Enviando o token

Depois de obter o token, podemos enviá-lo utilizando o header Authorization. 

curl -X GET https://serverest.dev/usuarios \-H "Authorization: Bearer <token>"

Substitua <token> pelo token retornado pela API.

Exemplo completo de requisição

Podemos combinar vários conceitos aprendidos: POST, JSON, headers e autenticação com Bearer Token. 

curl -X POST https://serverest.dev/produtos \-H "Content-Type: application/json" \-H "Authorization: Bearer <token>" \-d '{    "nome": "Produto de teste",    "preco": 100,    "descricao": "Produto criado utilizando cURL",    "quantidade": 10}'

Entendendo o comando

  1. -X POST — define o método HTTP como POST.
  2. Content-Type: application/json — informa que os dados enviados estão no formato JSON.
  3. Authorization: Bearer <token> — envia o token utilizado para autenticação.
  4. -d '{...}' — define o body da requisição, contendo os dados do produto.
  5. https://serverest.dev/produtos — é o endpoint utilizado para criar o produto.

Resumindo

Em uma API que utiliza autenticação, o processo normalmente consiste em:

  • Realizar o login.
  • Enviar as credenciais para a API.
  • Obter o token de autenticação.
  • Enviar o token no header Authorization.
  • Acessar os endpoints protegidos. 
Login↓Token↓Authorization: Bearer <token>↓Endpoint protegido
QA Note

Em testes de API, é comum separar o processo de autenticação do teste do endpoint protegido. Primeiro obtemos o token e, em seguida, utilizamos esse token no header Authorization das requisições que exigem autenticação.
