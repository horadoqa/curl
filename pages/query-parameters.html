Query Parameters

cURL / Query Parameters

O que são Query Parameters?

Query Parameters são parâmetros enviados diretamente na URL para fornecer informações adicionais ao servidor durante uma requisição HTTP.

Eles normalmente são utilizados para realizar filtros, buscas, ordenação e paginação dos dados retornados por uma API.

Estrutura da URL

Os Query Parameters aparecem depois do caractere ? na URL. 

https://serverest.dev/usuarios?nome=hora%20do%20QA

Nesse exemplo, temos: 

https://serverest.dev/usuarios                         │                         └── endpoint?nome=hora%20do%20QA│    ││    └── valor└────── parâmetro

Realizando uma consulta

Podemos utilizar o cURL para enviar uma requisição contendo um parâmetro de consulta. 

curl "https://serverest.dev/usuarios?nome=hora%20do%20QA"

Nesse caso, o parâmetro utilizado é nome e o valor informado é hora do QA.

Parâmetro e valor

Um Query Parameter normalmente segue o formato: 

?parametro=valor

No nosso exemplo: 

?nome=hora%20do%20QA

O ? indica o início dos parâmetros, enquanto nome representa o parâmetro e o valor enviado é hora do QA.

URL Encoding

Como espaços não são utilizados diretamente em uma URL, eles podem ser representados utilizando %20. 

hora do QA↓hora%20do%20QA

Dessa forma, a URL completa fica: 

curl "https://serverest.dev/usuarios?nome=hora%20do%20QA"

Utilizando vários parâmetros

Uma URL pode possuir mais de um Query Parameter. Nesse caso, utilizamos o caractere & para separar os parâmetros. 

curl "https://api.exemplo.com/usuarios?nome=joao&idade=30"

A estrutura pode ser representada da seguinte forma: 

?nome=joao&idade=30│       ││       └── segundo parâmetro└────────── primeiro parâmetro

Utilizando filtros

APIs frequentemente utilizam Query Parameters para filtrar os dados retornados. 

curl "https://api.exemplo.com/produtos?nome=Notebook"

Nesse caso, estamos solicitando ao servidor dados relacionados ao nome informado no parâmetro.

Paginação

Outro uso muito comum dos Query Parameters é controlar a paginação dos resultados. 

curl "https://api.exemplo.com/usuarios?pagina=2&limite=10"

Nesse exemplo, a aplicação recebe dois parâmetros: pagina e limite.

Parâmetro Valor Função
pagina 2 Define a página solicitada.
limite 10 Define a quantidade de registros.

Query Parameters em testes de API

Durante testes de API, Query Parameters são importantes para validar diferentes cenários de consulta.

  • Validar filtros.
  • Validar buscas por diferentes valores.
  • Testar paginação.
  • Validar parâmetros obrigatórios.
  • Testar parâmetros inválidos.
  • Verificar o comportamento quando nenhum resultado é encontrado.

Combinando Query Parameters e Status Code

Podemos combinar Query Parameters com o recurso de captura do Status Code que já vimos anteriormente. 

STATUS=$(curl -s \  -o resposta.json \  -w "%{http_code}" \  "https://serverest.dev/usuarios?nome=hora%20do%20QA")echo "Status Code: $STATUS"

Dessa forma, podemos validar tanto o conteúdo da consulta quanto o Status Code retornado pela API.

Resumindo

Query Parameters permitem enviar informações adicionais para a API através da URL. 

curl "https://serverest.dev/usuarios?nome=hora%20do%20QA"

Quando precisamos enviar mais de um parâmetro, utilizamos & para separá-los: 

curl "https://api.exemplo.com/usuarios?nome=joao&pagina=2"
QA Note

Query Parameters são muito utilizados em testes de API para validar filtros, buscas e paginação. Ao automatizar esses cenários com cURL, podemos combinar os parâmetros da URL com Status Codes, arquivos de resposta e ferramentas como jq para criar validações mais completas.
