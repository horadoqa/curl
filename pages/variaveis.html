Trabalhando com Variáveis de Ambiente

cURL / Environment Variables

Por que utilizar variáveis?

Durante a automação de testes de API, podemos precisar utilizar informações como tokens, URLs, usuários, senhas ou outras configurações.

Em vez de colocar essas informações diretamente no script, podemos armazená-las em variáveis de ambiente e acessá-las durante a execução.

Criando uma variável

No terminal, podemos criar uma variável de ambiente utilizando o comando export. 

export TOKEN="eyJhbGciOiJIUzI1NiIs..."

Nesse exemplo, o valor do token é armazenado na variável chamada TOKEN.

Utilizando a variável no cURL

Depois de criar a variável, podemos utilizá-la dentro do comando cURL utilizando o símbolo $. 

curl \  -H "Authorization: Bearer $TOKEN" \  https://serverest.dev/usuarios

Entendendo o comando

  • export cria uma variável de ambiente disponível para os processos iniciados pelo shell.
  • TOKEN é o nome da variável utilizada para armazenar o token.
  • $TOKEN acessa o valor armazenado nessa variável.
  • Authorization: Bearer $TOKEN envia o token no header da requisição.

Token direto vs variável

Uma abordagem menos adequada para scripts é colocar diretamente o token no comando: 

curl \  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \  https://serverest.dev/usuarios

Podemos substituir o valor diretamente exposto pela variável de ambiente: 

curl \  -H "Authorization: Bearer $TOKEN" \  https://serverest.dev/usuarios

Variáveis para diferentes ambientes

O mesmo conceito pode ser utilizado para armazenar diferentes URLs de API. 

export BASE_URL="https://serverest.dev"curl "$BASE_URL/usuarios"

Também podemos combinar diferentes variáveis: 

export BASE_URL="https://serverest.dev"export TOKEN="eyJhbGciOiJIUzI1NiIs..."curl \  -H "Authorization: Bearer $TOKEN" \  "$BASE_URL/usuarios"

Utilizando em um script

As variáveis de ambiente também podem ser utilizadas dentro de scripts de automação. 

#!/bin/bashcurl \  -H "Authorization: Bearer $TOKEN" \  "$BASE_URL/usuarios"

Nesse cenário, o script não precisa necessariamente conter os valores específicos do ambiente.

Boas práticas

  • Evite colocar tokens diretamente no código-fonte.
  • Utilize variáveis de ambiente para configurações específicas do ambiente.
  • Evite versionar arquivos que contenham credenciais reais.
  • Utilize valores diferentes para ambientes de desenvolvimento, teste e produção quando necessário.
  • Em pipelines de CI/CD, prefira mecanismos de secrets fornecidos pela própria plataforma.

Exemplo completo 

export BASE_URL="https://serverest.dev"export TOKEN="eyJhbGciOiJIUzI1NiIs..."echo "Consultando API..."curl \  -H "Authorization: Bearer $TOKEN" \  "$BASE_URL/usuarios"

Resumindo

Para armazenar um token em uma variável de ambiente: 

export TOKEN="seu-token"

E utilizá-lo no cURL: 

curl \  -H "Authorization: Bearer $TOKEN" \  https://serverest.dev/usuarios
QA Note

Utilizar variáveis de ambiente ajuda a separar configuração e credenciais do código do teste. Em automações de QA e pipelines de CI/CD, essa abordagem facilita a utilização do mesmo script em diferentes ambientes e reduz o risco de colocar tokens diretamente no código-fonte.
