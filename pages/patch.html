CONCEITO / 09 HTTP / PATCH

Atualizando Recursos com PATCH

cURL / Partial Update

O que é PATCH?

O método HTTP PATCH é utilizado quando precisamos realizar uma atualização parcial de um recurso existente.

Diferentemente de uma atualização completa, podemos enviar somente os campos que precisam ser modificados.

Comando 

curl -X PATCH https://serverest.dev/usuarios/ID \     -H "Content-Type: application/json" \     -d '{"nome":"Novo Nome"}'

Entendendo a requisição

O comando possui três elementos principais: o método HTTP, o header que identifica o formato dos dados e o corpo da requisição.

  • -X PATCH define o método HTTP utilizado na requisição.
  • https://serverest.dev/usuarios/ID representa o endpoint do usuário que será atualizado.
  • -H "Content-Type: application/json" informa que o corpo da requisição está no formato JSON.
  • -d '{"nome":"Novo Nome"}' envia o campo que será atualizado.

Identificando o recurso

O ID presente na URL representa o recurso que será alterado. 

https://serverest.dev/usuarios/ID

Por exemplo, caso o ID do usuário seja abc123, a URL poderia ser: 

https://serverest.dev/usuarios/abc123

Corpo da requisição

O corpo contém somente o campo que queremos modificar: 

{  "nome": "Novo Nome"}

Nesse caso, estamos solicitando que apenas o campo nome seja atualizado.

PATCH vs PUT

Uma diferença importante em testes de API é entender a finalidade de PATCH e PUT.

Método Utilização
PATCH Atualização parcial de um recurso.
PUT Utilizado para uma atualização do recurso conforme a representação enviada pela API.

Atualizando outros campos

Podemos enviar mais de um campo no mesmo JSON, caso a API permita essa atualização. 

curl -X PATCH https://serverest.dev/usuarios/ID \     -H "Content-Type: application/json" \     -d '{       "nome": "Novo Nome",       "password": "novaSenha123"     }'

Verificando o Status Code

Durante um teste de API, podemos utilizar o -w para visualizar o Status Code retornado pelo servidor. 

curl -s -o resposta.json -w "%{http_code}" \     -X PATCH https://serverest.dev/usuarios/ID \     -H "Content-Type: application/json" \     -d '{"nome":"Novo Nome"}'

Dessa forma, podemos separar o corpo da resposta do Status Code retornado pela API.

Validando o resultado

Em uma automação de QA, podemos utilizar o Status Code para determinar se o teste deve continuar ou falhar. 

STATUS=$(curl -s \  -o resposta.json \  -w "%{http_code}" \  -X PATCH https://serverest.dev/usuarios/ID \  -H "Content-Type: application/json" \  -d '{"nome":"Novo Nome"}')if [ "$STATUS" -eq 200 ]; then  echo "Usuário atualizado com sucesso"else  echo "Falha ao atualizar usuário"  exit 1fi

Resumindo

Para realizar uma atualização parcial utilizando o cURL, podemos utilizar: 

curl -X PATCH <URL> \     -H "Content-Type: application/json" \     -d '{"campo":"novo valor"}'
  • PATCH indica uma atualização parcial.
  • O ID identifica o recurso que será atualizado.
  • Content-Type: application/json informa o formato do corpo.
  • -d envia os dados que serão utilizados na atualização.
  • O Status Code pode ser utilizado para validar o resultado do teste.
QA Note

Em testes de API, o PATCH é especialmente útil para validar atualizações parciais. Uma boa prática é verificar não apenas o Status Code, mas também consultar o recurso posteriormente para confirmar que o campo esperado foi realmente alterado.
