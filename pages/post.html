Como utilizar o cURL para enviar dados ao servidor e criar um novo usuário através de uma requisição HTTP POST no ServeRest.

CONCEITO / 01 CREATE / POST

POST Request

HTTP / CREATE

A requisição POST é utilizada para enviar dados ao servidor, geralmente com o objetivo de criar um novo recurso.

No ServeRest, podemos utilizar o método POST para cadastrar um novo usuário.

ENDPOINT / 01 USERS

Endpoint

POST / usuarios 
POST https://serverest.dev/usuarios
EXEMPLO / 01 REQUEST

Criando um usuário

cURL + JSON 
curl -X POST https://serverest.dev/usuarios \-H "Content-Type: application/json" \-d '{    "nome": "Hora do QA",    "email": "horadoqa@email.com",    "password": "1q2w3e4r",    "administrador": "true"}'
EXPLICAÇÃO / 01 HOW IT WORKS

Entendendo a requisição

Método HTTP

-X POST: define o método HTTP como POST.

Content-Type

-H "Content-Type: application/json": informa ao servidor que os dados enviados estão no formato JSON.

Request Body

-d '{...}': define o body da requisição, ou seja, os dados que serão enviados para o servidor.

Dados enviados 
{    "nome": "Hora do QA",    "email": "horadoqa@email.com",    "password": "1q2w3e4r",    "administrador": "true"}

Nesse exemplo, estamos enviando os dados de um novo usuário para o servidor.

O servidor recebe essas informações, valida os dados e tenta criar um novo cadastro.

RESPONSE / 01 201 CREATED

Resposta de sucesso

HTTP / Created

Quando o cadastro é realizado com sucesso, o ServeRest retorna o status 201 Created, indicando que um novo recurso foi criado. 

{    "message": "Cadastro realizado com sucesso",    "_id": "7tS9K8NxabeHLEtk"}

A resposta contém uma mensagem de confirmação e o _id gerado para o novo usuário.

O _id é um identificador único utilizado para localizar esse usuário em outras requisições, como GET, PUT e DELETE.

RESPONSE / 02 VALIDATION

E-mail já cadastrado

Regra de negócio

O campo email deve ser único. Portanto, se tentarmos cadastrar outro usuário utilizando um e-mail que já existe, o ServeRest retornará uma mensagem informando que o e-mail já está sendo utilizado. 

{    "message": "Este email já está sendo usado"}
QA Note

Em testes de API, cenários de sucesso e de validação devem ser considerados. Além do 201 Created, vale testar regras como e-mail duplicado e dados inválidos.

RESUMO / 01 CRUD / CREATE

POST = Create

Fluxo de criação 
1. Utilizar o método POST2. Informar o endpoint /usuarios3. Enviar os dados no body4. Enviar os dados em formato JSON5. O servidor valida os dados6. Um novo usuário é criado7. O servidor retorna o _id

O POST representa a operação Create no CRUD: enviar dados ao servidor para criar um novo recurso.

QA Note

O resultado esperado de uma criação bem-sucedida é o status 201 Created. O identificador retornado pode ser utilizado nas próximas etapas do teste, como consultas com GET, alterações com PUT ou exclusão com DELETE.
