Salvando e validando respostas

Durante testes de API, frequentemente precisamos armazenar a resposta, analisar seu conteúdo, validar o Status Code e, em alguns casos, baixar arquivos.

01 · Salvando a resposta

Para salvar a resposta de uma requisição em um arquivo, utilizamos a opção -o, também conhecida como --output. 

curl -o resposta.json https://serverest.dev/usuarios

Nesse comando, o -o define o arquivo de saída. O nome resposta.json será utilizado para armazenar o corpo retornado pela API. 

resposta.json

02 · Visualizando a resposta

Depois de salvar a resposta, podemos utilizar o cat para visualizar o conteúdo do arquivo. 

cat resposta.json

Quando a API retorna JSON, podemos utilizar o jq para apresentar o conteúdo de forma mais organizada. 

jq . resposta.jsoncat resposta.json | jq .

03 · POST + arquivo

A opção -o pode ser utilizada com qualquer método HTTP, incluindo requisições POST. 

curl -X POST "https://serverest.dev/usuarios" \  -H "Content-Type: application/json" \  -d '{    "nome": "Hora do QA",    "email": "horadoqa@example.com",    "password": "1q2w3e4r",    "administrador": "false"  }' \  -o resposta.json

Depois da execução, a resposta poderá ser analisada utilizando: 

jq . resposta.json

04 · -o vs -O

É importante diferenciar as opções -o e -O. 

curl -o resposta.json https://serverest.dev/usuarioscurl -O https://exemplo.com/relatorio.pdf
Opção Comportamento
-o arquivo Define o nome do arquivo.
-O Utiliza o nome do arquivo presente na URL. 
-o → eu escolho o nome-O → a URL define o nome

05 · Capturando o Status Code

Em testes de API, muitas vezes não basta salvar o corpo da resposta. Também precisamos saber se a requisição foi processada corretamente. 

curl -s \  -o resposta.json \  -w "%{http_code}" \  https://serverest.dev/usuarios

Nesse exemplo:

  • -s executa o cURL em modo silencioso.
  • -o resposta.json salva o corpo da resposta.
  • -w "%{http_code}" exibe o Status Code HTTP. 
200

06 · Armazenando o Status Code

Em automação, podemos armazenar o Status Code em uma variável para utilizá-lo posteriormente em uma validação. 

STATUS=$(curl -s \  -o resposta.json \  -w "%{http_code}" \  https://serverest.dev/usuarios)echo "$STATUS"

Dessa forma, temos duas informações separadas: 

STATUS↓200resposta.json↓Corpo da resposta da API

07 · Validando com if

O Status Code pode ser utilizado para decidir se o teste deve continuar ou ser interrompido. 

STATUS=$(curl -s \  -o resposta.json \  -w "%{http_code}" \  https://serverest.dev/usuarios)if [ "$STATUS" -eq 200 ]; then  echo "API disponível - Status Code: $STATUS"  jq . resposta.jsonelse  echo "API indisponível - Status Code: $STATUS"  jq . resposta.json  exit 1fi

08 · Baixando arquivos

O cURL também pode ser utilizado para baixar arquivos. Com -O, o nome do arquivo é obtido diretamente da URL. 

curl -O https://exemplo.com/arquivo.zipcurl -O https://exemplo.com/relatorio.pdf

Podemos também definir um nome personalizado utilizando -o. 

curl -o meu-relatorio.pdf https://exemplo.com/relatorio.pdf

09 · Baixando para uma pasta

Podemos especificar o caminho completo onde o arquivo deverá ser salvo. 

mkdir -p downloadscurl -o ./downloads/relatorio.pdf \  https://exemplo.com/relatorio.pdf

Nesse caso, o arquivo será salvo em: 

downloads/relatorio.pdf

10 · Continuando um download

Se um download for interrompido, podemos utilizar -C - para tentar continuar a partir do ponto em que parou. 

curl -C - -O https://exemplo.com/arquivo.zip

11 · Exemplo completo de automação

Podemos combinar essas funcionalidades em um pequeno teste automatizado utilizando Bash, cURL e jq. 

#!/bin/bashURL="https://serverest.dev/usuarios"ARQUIVO="resposta.json"echo "Consultando API..."STATUS=$(curl -s \  -o "$ARQUIVO" \  -w "%{http_code}" \  "$URL")echo "Status Code: $STATUS"if [ "$STATUS" -eq 200 ]; then  echo "Teste aprovado"  echo ""  echo "Resposta da API:"  jq . "$ARQUIVO"else  echo "Teste reprovado"  echo ""  echo "Resposta da API:"  jq . "$ARQUIVO"  exit 1fi

Principais opções utilizadas

Opção Função
-X Define o método HTTP.
-H Adiciona um Header.
-d Envia dados no corpo da requisição.
-o Salva a resposta em um arquivo com nome definido.
-O Salva utilizando o nome do arquivo da URL.
-s Executa o cURL em modo silencioso.
-w Permite formatar informações da resposta.
%{http_code} Obtém o Status Code HTTP.
-C - Continua um download interrompido.

cURL além da requisição

O cURL vai muito além de simplesmente fazer uma requisição HTTP. Em automação de testes, podemos utilizá-lo para trabalhar com respostas, Status Codes, arquivos e validações.

  • Realizar requisições HTTP.
  • Enviar Headers e payloads.
  • Salvar respostas em arquivos.
  • Analisar JSON com jq.
  • Capturar Status Codes.
  • Validar condições com if.
  • Interromper testes com exit 1.
  • Baixar arquivos.
  • Continuar downloads interrompidos.
  • Gerar evidências para análise dos testes.
QA Note

Uma estrutura muito útil para automação de QA é separar o corpo da resposta e o Status Code. Dessa forma, o teste consegue analisar o conteúdo retornado e, ao mesmo tempo, decidir automaticamente se deve continuar ou falhar utilizando if e exit 1.
