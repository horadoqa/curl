Adicionando Cabeçalhos

cURL / HTTP Headers

O que são Headers?

Os headers são informações adicionais enviadas junto com uma requisição HTTP. Eles podem fornecer instruções ou informações ao servidor sobre como a requisição deve ser interpretada.

No cURL, podemos adicionar um cabeçalho utilizando a opção -H, também conhecida como --header.

Comando 

curl -H "Nome-Do-Header: valor" https://api.exemplo.com/usuarios

Exemplo

Podemos utilizar o header Authorization para enviar um token de autenticação para uma API. 

curl -X GET https://api.exemplo.com/usuarios \-H "Authorization: Bearer <token>"

Entendendo o Header

Nesse exemplo, estamos enviando o seguinte cabeçalho: 

Authorization: Bearer <token>

O header possui três partes principais: 

Authorization: Bearer <token>Authorization → nome do headerBearer       → tipo de autenticação<token>       → token de acesso

Na prática, o <token> deve ser substituído pelo token real fornecido pela API. 

curl -X GET https://api.exemplo.com/usuarios \-H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."

O servidor pode utilizar esse token para verificar se o cliente possui autorização para acessar determinado recurso.

Outros Headers

Além do Authorization, existem outros headers muito utilizados em APIs.

Para informar que estamos enviando dados em JSON, podemos utilizar: 

-H "Content-Type: application/json"

Para informar que esperamos receber uma resposta em JSON: 

-H "Accept: application/json"

Vários Headers

Também podemos enviar vários headers na mesma requisição. 

curl -X POST https://api.exemplo.com/usuarios \-H "Content-Type: application/json" \-H "Accept: application/json" \-H "Authorization: Bearer <token>" \-d '{    "nome": "Hora do QA",    "email": "horadoqa@email.com"}'

Resumindo

A opção -H permite adicionar um cabeçalho à requisição HTTP. 

-H "Nome-Do-Header: valor"

Os headers são utilizados em diversas situações, principalmente para autenticação, definição do formato dos dados enviados e definição do formato esperado da resposta.

QA Note

Headers fazem parte da comunicação entre cliente e servidor. Em testes de API, é importante observar principalmente Authorization, Content-Type e Accept. A opção -H permite adicionar esses cabeçalhos diretamente na requisição cURL.
